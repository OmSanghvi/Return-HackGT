  ## Real bugs found and fixed
  1. **infra/aws/main.tf — S3 IAM policy gap.**
  `aws_iam_role_policy.artifacts_bucket` only granted
  `s3:PutObject/GetObject/DeleteObject` on `artifacts/*`.
  `ArtifactStore.put_upload`/`open_upload` (Build Plan step 26) write under
  `uploads/<project_id>/<upload_id>/...` — a completely different prefix. Once
  activated, every real upload call would get `AccessDenied`. Fixed by adding
  `uploads/*` to the Resource list.
  2. **infra/aws/main.tf — DynamoDB IAM policy gap.**
  `aws_iam_role_policy.dynamodb_authoring` only granted access to the base table
  ARN. AWS IAM evaluates a `Query` with `IndexName` against the index's own ARN
  (`.../index/<name>`), a distinct resource — so every `gsi1`/`gsi2` query
  (`list_project_jobs`, `claim_next_job`, `release_expired_leases`) would get
  `AccessDenied` even though plain reads/writes worked. Fixed by adding `"<table
  arn>/index/*"`.
  3. **backend/storage.py — missing pagination.** `list_project_jobs`,
  `claim_next_job`, and `release_expired_leases` each issued a single
  unpaginated DynamoDB `Query` (unlike the existing `_query_children`, which
  already loops on `LastEvaluatedKey`). A busy project or job backlog beyond one
  page would silently drop jobs from listings, or `claim_next_job` could return
  "no job available" even when a matching-kind job existed on a later page.
  Added a paginated `_query_index` helper mirroring `_query_children`'s loop and
  switched all three methods to it. Added tests using a table-proxy that forces
  `Limit=1` (via moto) to force genuine multi-page traversal at trivial item
  counts, since a hermetic test can't otherwise make a real DynamoDB response
  span pages.
  4. **scripts/smoke_test_aws_storage.py — coverage gap that let bugs 1 and 2 go
  undetected.** The live smoke test never exercised the `uploads/` S3 prefix,
  jobs, contributors/contributions/insights, or the LIVE pointer — only the
  legacy `artifacts/` PLY path and basic project/asset/blueprint CRUD. Extended
  it to cover all of the above with matching cleanup (including the `JOB#` item,
  which lives under its own pk and isn't swept by the `PROJECT#` scan). Dry-ran
  the extended script against a moto-mocked table/bucket shaped exactly like
  the real Terraform resources to confirm correctness before it's ever pointed
  at real AWS — exit code 0, all checks passed.
